# doit-pt2 — 다크 골드 제안 덱 생성

브랜드 캠페인·클라이언트 제안을 **광고대행사 제안서 수준의 HTML 프레젠테이션**으로 만든다. `삿포로_EX_PROGRAM_v20.pptx`에서 추출한 디자인 시스템.

## 트리거

`/doit-pt2` 또는 제안서·캠페인 덱·클라이언트 PT 요청

## 언제 쓰나

- 외부 클라이언트에게 제안하는 덱 — 브랜드 톤이 필요하고 화면 목업·대시보드·고객 동선이 들어갈 때
- (구분) `/doit-pt` = 흑백 에디토리얼 세로 흐름 · **`/doit-pt2` = 다크 골드 16:9 고정 조판** · `/doit-report` = A4 PDF 리포트

## 형식 (핵심 — 임의 변경 금지)

- **고정 1280×720 캔버스**: 모든 수치는 디자인 px. `.stage`를 `transform: scale(--s)`로 뷰포트에 맞춤(JS가 계산). 16:9 비율이 어디서나 유지된다.
- **배경 교차 리듬**: 먹빛 `#090909`(표지·구조·역할) ↔ 크림 `#FBF8F2` / `#F5F1E8`(동선·문항·비용). 연속 3장 같은 배경 금지.
- **골드 규칙**: 라이트 배경 위 골드는 `#8C6B2B`, 다크 배경 위는 `#C9A457`. `.is-dark`가 자동 전환.
- **레드는 한 장에 한 곳**: `#C91F2C`는 그 슬라이드에서 가장 중요한 항목 하나에만. `.hot` 클래스.
- **타이포**: Noto Sans KR(Google Fonts). 표지 72px / 제목 40px / 카드 21px / 본문 17px / 캡션 15px / 키커 13px.
- 색·좌표·타입스케일은 `assets/pt2-skeleton.html`의 `<style>`에 정의됨 — **그대로 유지한다.**

## 슬라이드 타입 (마크업은 `assets/pt2-skeleton.html` — 복제해서 텍스트만 교체)

| 클래스 | 용도 | 배경 | 핵심 요소 |
|---|---|---|---|
| `t-cover` | 표지 | 다크 | 우측 이미지 + `.brand`·`.display`·`.rule`·`.sub`·`.tag`·`.by` (고정 좌표) |
| `t-divider` | 섹션 구분 | 다크 | `.kicker`·`.h1`·`.lead` 세로 중앙 |
| `t-cols3` | 3축 요약 | 다크/라이트 | `.hair` + `.cols` > `.num`·`.ct`·`.cd` ×3 |
| `t-panel3` | 대시보드·구조 | 다크 | `.panel`(프레임) > `.panel-head` + 세로선 3분할 + `.tag` |
| `t-list-media` | 목록 + 이미지 | 라이트 | 좌 `.rows`(번호·이름·설명) + 우 `.media` + `.note` |
| `t-steps` | 가로 단계(4~6) | 라이트 | `.track` > `.line` + `.dot`·`.st`·`.sd` + `.infobar` |
| `t-duo` | 2축 대비 | 라이트 | `.pane` ×2 (골드 테두리) + `.stmt` + `.fine` |
| `t-cycle` | 순환 구조 | 라이트 | 4모서리 `.cell` + 중앙 `.hub`(다크 타원) + `.arw` |
| `t-screens` | 화면 목업 | 라이트 | `.msg`(문구 카드) + `.frame` ×3 + `.cta` |
| `t-spec6` | 항목·비용 표 | 라이트 | 2열 `.item` ×6 (번호·이름·설명·값) + `.close` |

## 공통 컴포넌트

- `.kicker`(영문 대문자 라벨) · `h1` · `.lead`(한 문장 요약) · `.rule`(골드 2px) · `.hair`(헤어라인)
- `.num`(번호, `.hot`이면 레드) · `.note`(둥근 보충 박스) · `.footrows` > `.footrow`(라벨+내용) · `.fine`(각주)
- `.pageno` — **모든 슬라이드에 필수**, `01`부터 총 장수까지

## 빌드 절차

1. **스켈레톤 복사**: `assets/pt2-skeleton.html`을 작업 위치로 복사.
2. **`<style>`·`<script>`·`.deck`·`.stage`는 건드리지 않는다.** (형식의 핵심)
3. `.deck` 안 `<section>`을 주제에 맞는 타입으로 재구성. 스켈레톤의 동일 타입을 복제해 텍스트만 교체.
4. 표지 → 본문 → (필요 시 `t-divider` + 부록) 순. **한 슬라이드 = 한 메시지.**
5. `.pageno`를 `01`…`N`으로 갱신, `<title>`·표지 텍스트를 주제에 맞게.
6. **이미지**: `<img src>`에 경로를 넣거나 `data:image/jpeg;base64,…`로 임베드(단일 파일 공유 시). 1000px 폭·JPEG 78 정도로 줄여 임베드한다.
7. **저장**: `<주제>_PT.html`.
8. **열기**: 브라우저 확인. PDF는 인쇄(가로·배경 그래픽 켜기) — `@media print`가 1280×720 페이지로 잡아준다.

## 원칙

- 정보 밀도: `.lead` 1문장, `.cd`/`.rd` 2줄 이내, `li` 짧게. 고정 캔버스라 넘치면 잘린다 — **글자 수를 줄이지, 폰트를 줄이지 않는다.**
- 제목은 `<br>`로 의미 단위 2줄까지. 한글 줄바꿈은 `word-break: keep-all`이 처리.
- 레드 `.hot`은 슬라이드당 1개소. 남발하면 위계가 죽는다.
- 다크 슬라이드는 구조·권위(표지·대시보드·역할 분담), 라이트 슬라이드는 흐름·디테일(동선·문항·비용)에 쓴다.
- 인터넷 필요(Noto Sans KR CDN). 오프라인 배포 시 woff2 로컬 임베드.
